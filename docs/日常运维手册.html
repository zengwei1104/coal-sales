一、系统概览

系统由三个 Docker 容器组成，全部在部署目录 /opt/coal-sales 下通过 docker compose 统一管理：

容器服务名作用对外端口
mysqlmysql数据库无（内部网络）
backendbackend后端接口无（内部网络）
webweb前端页面 + Nginx 转发80

⚠️ 所有命令都必须在部署目录里执行，先 cd /opt/coal-sales，否则会报「找不到 docker-compose.yml」。

二、日常启动 / 关闭 / 重启

这是最常用的操作。先进入部署目录：

cd /opt/coal-sales

▶️ 启动（开机后 / 停止后重新启动）

用已有的镜像启动所有容器，不重新编译，速度最快。

docker compose up -d

⏸️ 停止（保留容器和数据，临时关闭）

停止运行中的容器，但不删除容器和数据，随时可以再启动。

docker compose stop

▶️ 再次启动（对应上面的 stop）

docker compose start

🔄 重启（快速重启所有服务）

docker compose restart

🛑 彻底停止并删除容器（数据不丢）

删除所有容器。数据库数据存在 Docker 卷里，不会丢失，下次 up -d 会重新创建容器并复用数据。

docker compose down
记住这两个就够了：
· 平时开关 → docker compose stop / docker compose start
· 更新代码 → git pull + docker compose up -d --build

三、更新代码后重新部署

改了代码并 push 到远程仓库后，在虚拟机里这样更新：

1. 拉取最新代码

cd /opt/coal-sales
git pull

2. 重新编译 + 启动

docker compose up -d --build

--build 会重新执行 Dockerfile 编译代码，改了代码就必须加这个参数，否则会用旧镜像。

四、查看状态与日志

📋 查看容器状态

三个容器都应显示 running（或 Up）。

docker compose ps

📄 查看日志（实时滚动）

docker compose logs -f web       # 前端
docker compose logs -f backend   # 后端
docker compose logs -f mysql     # 数据库

按 Ctrl+C 退出日志查看（不影响容器运行）。

📄 查看最近 100 行日志（不实时）

docker compose logs --tail 100 backend

六、常见问题

问题排查 / 解决
提示「找不到 docker-compose.yml」没进对目录，先 cd /opt/coal-sales
页面打不开先 docker compose ps 看三个容器是否都 running；再 docker compose logs -f backend 看后端是否报错
改了代码但没生效是不是忘了加 --build？更新必须用 docker compose up -d --build
重启后数据还在吗在。数据库数据存在 mysql-data 卷里，stop / restart / down 都不会丢
想彻底清空数据库重来删除卷：docker compose down -v（⚠️ 会删除所有数据，慎用）
