## 1 全局约定

### 1.1 Base URL 与版本

```
开发环境：http://localhost:8080/api
生产环境：Nginx 将 /api 反向代理至后端
```

所有接口统一以 `/api` 为前缀，由 Nginx 或 Spring 的 `server.servlet.context-path` 处理。

### 1.2 RESTful 资源命名规则

| 规则 | 说明 | 示例 |
| --- | --- | --- |
| 资源用**名词复数** | 不用动词，动作由 HTTP 方法表达 | `/customers`、`/contracts` |
| 单资源用 `/资源/{id}` | 定位到具体一条 | `GET /customers/5` |
| 子资源用层级 | 表达从属关系 | `GET /contracts/5/orders` |
| 动作型操作用子资源或 `POST /动作` | 无法用 CRUD 表达的动作用动词子资源 | `POST /orders/5/cancel` |

### 1.3 HTTP 方法语义

| 方法 | 用途 |
| --- | --- |
| GET | 查询（列表、详情） |
| POST | 新增、动作（审核、作废、过磅等） |
| PUT | 整体更新（较少用，本项目更新统一用 PUT） |
| DELETE | 删除（逻辑删除） |

### 1.4 统一返回结构 `Result<T>`

所有接口返回 JSON 结构如下：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 状态码，200 成功，其余为业务/系统错误 |
| message | string | 提示信息，失败时给出可理解的中文 |
| data | object | 业务数据，可为对象、数组或 null |

### 1.5 分页参数与返回

**请求**（GET 列表接口统一用 query 参数）：

| 参数 | 说明 | 默认 |
| --- | --- | --- |
| page | 页码，从 1 开始 | 1 |
| size | 每页条数 | 10 |
| 其他 | 业务筛选条件（关键字、状态等） | —— |

**返回**（统一分页结构 `PageResult<T>`）：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "records": [ { } ],
    "total": 120,
    "page": 1,
    "size": 10
  }
}
```

### 1.6 鉴权约定

- 登录成功返回 `token`，前端存 localStorage，后续请求头携带：`Authorization: Bearer <token>`
- 除登录接口外，其余接口均需携带 token
- token 无效/过期 → 返回 401；权限不足 → 返回 403

### 1.7 错误码

| code | 含义 | 说明 |
| --- | --- | --- |
| 200 | 成功 | |
| 400 | 参数错误 | 入参校验失败，message 指明具体字段 |
| 401 | 未认证 | 未登录或 token 失效 |
| 403 | 越权 | 已登录但无此操作权限 |
| 404 | 资源不存在 | 查询/操作的目标记录不存在 |
| 500 | 系统异常 | 服务端未捕获异常，不向前端暴露堆栈 |
| 1001 | 业务异常 | 通用业务规则校验失败（库存不足、合同余量不足等），message 说明原因 |
| 1002 | 状态非法 | 单据状态不允许当前操作（如已完成订单不可修改） |

> 业务异常统一走 1001/1002，通过 message 区分具体场景，避免为每个规则单独设错误码导致膨胀。

## 2 认证与用户

### 2.1 登录

```
POST /api/auth/login
```

**请求体**：

```json
{
  "username": "admin",
  "password": "123456"
}
```

**响应**：

```json
{
  "code": 200,
  "message": "登录成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "userInfo": {
      "id": 1,
      "username": "admin",
      "realName": "系统管理员",
      "roleCode": "ADMIN",
      "menus": [ "/dashboard", "/system/user", "..." ]
    }
  }
}
```

> `menus` 为当前用户可访问的路由列表，前端据此渲染侧边栏；由后端按角色菜单查询后返回，前端不做权限判断。

### 2.2 退出登录

```
POST /api/auth/logout
```

前端清除本地 token 即可，服务端无会话。此接口仅用于记录退出日志，返回空 data。

### 2.3 修改密码

```
PUT /api/users/{id}/password
```

**请求体**：

```json
{
  "oldPassword": "123456",
  "newPassword": "abc12345"
}
```

## 4 销售链核心接口（重点）

### 4.1 合同

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/contracts` | 分页 + 状态/客户/煤种筛选，列表需带「剩余可下单量」 |
| GET | `/api/contracts/{id}` | 详情，含客户/煤种信息 |
| POST | `/api/contracts` | 新建（保存为草稿） |
| PUT | `/api/contracts/{id}` | 修改（仅草稿/被退回状态可改） |
| DELETE | `/api/contracts/{id}` | 删除（仅草稿可删） |
| POST | `/api/contracts/{id}/submit` | 提交审核（草稿 → 待审核） |
| POST | `/api/contracts/{id}/audit` | 审核（待审核 → 执行中/驳回） |

**新建合同请求体**：

```json
{
  "customerId": 1,
  "productId": 1,
  "signDate": "2026-10-26",
  "startDate": "2026-11-01",
  "endDate": "2027-10-31",
  "totalQty": 5000.000,
  "price": 520.00,
  "taxRate": 13.00,
  "qnetAr": 5500,
  "shortRate": 5.00,
  "payType": 3,
  "creditDays": 30,
  "transportBear": 1
}
```

**审核合同请求体**：

```json
{
  "pass": true,
  "opinion": "同意执行"
}
```

### 4.2 订单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/orders` | 分页 + 状态/客户/合同筛选 |
| GET | `/api/orders/{id}` | 详情，含合同、磅单列表 |
| POST | `/api/orders` | 新建（校验合同余量、信用额度） |
| PUT | `/api/orders/{id}` | 修改（计划量/单价/发货日期，校验见规则） |
| POST | `/api/orders/{id}/cancel` | 取消（仅未发运可取消） |

**新建订单请求体**：

```json
{
  "contractId": 8,
  "planQty": 300.000,
  "price": 520.00,
  "priceRemark": "",
  "deliveryDate": "2026-11-05",
  "plateNo": "晋B12345"
}
```

**订单修改请求体**（部分字段，只传要改的）：

```json
{
  "planQty": 350.000,
  "priceRemark": "客户加量议价"
}
```

> 修改规则（需求 R27–R31）：合同/客户/煤种不可改；计划量不得小于已发运量；改计划量须重校验合同余量（排除本单原量）；改价须填理由；已完成/已取消不可改。

### 4.3 磅单（称重发运）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/weigh-tickets` | 分页 + 状态/订单/车牌筛选 |
| GET | `/api/weigh-tickets/{id}` | 详情 |
| POST | `/api/weigh-tickets` | 新建（磅房选订单后创建，记皮重来源） |
| PUT | `/api/weigh-tickets/{id}/tare` | 录皮重（待称皮重 → 已称皮重） |
| PUT | `/api/weigh-tickets/{id}/gross` | 录毛重（已完成：算净重 + 扣库存 + 累加订单发运量） |
| POST | `/api/weigh-tickets/{id}/cancel` | 作废（仅未结算，须填原因） |

**新建磅单请求体**：

```json
{
  "orderId": 15,
  "plateNo": "晋B12345",
  "driver": "张三",
  "tareSource": 1
}
```

**录皮重请求体**：

```json
{
  "tareWeight": 16.800,
  "tareTime": "2026-10-26 09:15:00"
}
```

**录毛重请求体**：

```json
{
  "grossWeight": 49.850,
  "grossTime": "2026-10-26 10:30:00"
}
```

**作废请求体**：

```json
{
  "reason": "毛重录入错误"
}
```

> 录毛重是核心动作：净重 = 毛重 − 皮重，校验 20~40 吨区间；通过后在**同一事务**内完成「磅单置完成 → 扣库存 → 写库存流水 → 订单已发运量累加」。净重超出订单计划量×(1+超发阈值)时，磅单先置「待审批」状态，由销售经理审批。

### 4.4 订单/磅单的列表关联

- 磅房选订单：`GET /api/orders/available` —— 返回「待发运/部分发运」状态的订单（可过磅的）
- 销售员做结算选磅单：`GET /api/weigh-tickets/available` —— 返回「已完成且未结算」的磅单

## 5 财务接口（重点）

### 5.1 结算单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/settlements` | 分页 + 状态/客户筛选 |
| GET | `/api/settlements/{id}` | 详情，含明细列表 |
| POST | `/api/settlements` | 生成结算单（勾选磅单，按合同价算金额） |
| POST | `/api/settlements/{id}/audit` | 审核（待审核 → 已审核，计入应收） |
| POST | `/api/settlements/{id}/cancel` | 作废（未核销才可作废） |

**生成结算单请求体**：

```json
{
  "contractId": 8,
  "ticketIds": [ 101, 102, 103 ]
}
```

> 后端依磅单净重 × 单价（默认合同价）生成明细，`totalAmount = Σ明细金额`（R36，不用汇总净重重算）。改价需在明细级处理，附带改价理由。

**审核结算单请求体**：

```json
{
  "pass": true,
  "opinion": "核对无误"
}
```

### 5.2 回款与核销

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/payments` | 分页 + 客户筛选 |
| POST | `/api/payments` | 登记回款 |
| POST | `/api/payments/{id}/write-off` | 核销（一笔回款冲抵多张结算单） |
| GET | `/api/customers/{id}/receivable` | 客户应收账款（已审核未核销金额，实时计算） |

**登记回款请求体**：

```json
{
  "customerId": 1,
  "amount": 50000.00,
  "payType": 1,
  "payTime": "2026-10-26 14:00:00",
  "remark": "银行回单号 20261026-001"
}
```

**核销请求体**：

```json
{
  "items": [
    { "settleId": 20, "amount": 30000.00 },
    { "settleId": 21, "amount": 20000.00 }
  ]
}
```

> 核销金额合计不得超过回款金额；核销后结算单的「已收金额」由核销明细累加计算，不存冗余字段。

## 9 命名规范速查（编码时套用）

| 场景 | URL | 方法 |
