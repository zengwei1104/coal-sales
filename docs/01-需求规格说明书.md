## 1 引言

### 1.1 编写目的

明确系统的功能范围、业务规则、异常处理策略与非功能指标，作为概要设计、数据库设计、接口设计、测试用例编写的唯一依据。

预期读者：开发者本人、校内指导教师、企业指导教师、答辩评审组。

### 1.2 项目背景

煤炭贸易企业的销售链条长、单据多、对账复杂。一笔完整业务需经过**合同签订 → 订单录入 → 车辆过磅 → 结算开票 → 回款核销**五个环节，涉及销售、磅房、仓储、财务多个岗位。

目前中小贸易企业普遍依赖 Excel 与纸质磅单流转，存在三类问题：

| 问题                    | 后果                 |
| --------------------- | ------------------ |
| 磅单、订单、结算单各自独立，数据靠人工转录 | 数量口径不一致，三方对不上账     |
| 库存靠手工台账，无出入库流水        | 账面库存与实际长期偏差，损耗无法归因 |
| 客户信用额度无系统约束，回款无到期提醒   | 超额度发货、应收账款逾期       |

本系统将五个环节串为一条数据链，以**磅单净重**作为数量与金额的唯一计量依据，实现单证同源。

### 1.3 术语与缩略语

| 术语   | 说明                           |
| ---- | ---------------------------- |
| 磅单   | 车辆过磅记录，含皮重、毛重、净重、车牌、过磅时间、司磅员 |
| 毛重   | 载货状态下车辆总重（吨）                 |
| 皮重   | 空车自重（吨）                      |
| 净重   | 毛重 − 皮重，本次实际发运量              |
| 热值   | 单位质量煤炭燃烧释放热量（kcal/kg），定价核心指标 |
| 溢短装  | 合同约定允许超出或少于约定量的比例            |
| 结算   | 依据磅单净重与合同单价生成应收金额的过程         |
| 核销   | 将回款金额冲抵结算单，减少应收账款            |
| 账期   | 合同约定的付款期限，如「货到 30 天付款」       |
| 信用额度 | 允许客户欠款的上限金额                  |
| 安全库存 | 触发补货预警的库存下限                  |
| 盘盈盘亏 | 实际盘点数量与账面数量的差额               |

### 1.4 范围边界

**覆盖**：坑口直销（无库存直接过磅出厂）、煤场贸易（有库存先入库后销售）。

**本期不做**：真实支付渠道对接、车辆 GPS 轨迹、移动端 App 与小程序、金税发票开具、多仓调拨与仓位管理、港口/铁路下水煤业务、磅房地磅硬件直连、配煤与热值奖罚结算。

## 2 总体描述

### 2.1 系统目标

1. 打通「合同—订单—磅单—结算—回款」数据链，任一单据可追溯上下游。
2. 磅单净重自动驱动库存扣减与结算金额，消除人工转录误差。
3. 将信用额度、库存下限、发运超量三类风险前置到录入环节拦截。
4. 输出销售、库存、回款三类经营报表。

### 2.2 用户角色

| 角色    | 核心职责                         | 明确不能做               |
| ----- | ---------------------------- | ------------------- |
| 系统管理员 | 用户账号、角色菜单、数据字典、煤种商品基础数据、操作日志 | 不参与任何业务操作，不审核业务单据   |
| 销售经理  | 合同审核、超发审批、信用额度审批、经营报表查看      | 不录入业务单据             |
| 销售员   | 客户建档、合同录入、订单录入与修改、生成结算单      | 不能审核任何单据；不能自行调整信用额度 |
| 磅房人员  | 过磅称重、录入皮重/毛重、打印磅单、作废重录       | 不参与业务决策，只做计量记录      |
| 库管员   | 入库、出库、盘点、库存查询                | 不能改订单与结算单           |
| 财务人员  | 审核结算单、登记回款、对账、应收账款管理         | 不能录订单               |

**通用原则：谁创建，谁不能审核。**

> 角色拆分依据：系统管理员是 IT 角色，只维护系统运转；业务审批由销售经理承担，对应企业中的销售经理/总经理岗位。两条线互不越界，避免「IT 人员决定业务」的权限错位。

### 2.3 角色作业特征与界面要求

不同角色在流程中的位置决定了他们对系统的诉求完全不同。同样是「一个列表页」，销售员要的是能算、库管员要的是能查、磅房人员要的是能快。

#### 2.3.1 角色与业务环节的对应关系

| 角色    | 合同签订 | 订单录入 | 过磅称重 | 结算 | 回款 | 库存维护 |
| ----- | ---- | ---- | ---- | -- | -- | ---- |
| 系统管理员 |      |      |      |    |    |      |
| 销售经理  | 审核   |      |      |    |    |      |
| 销售员   | 主责   | 主责   |      | 主责 | 查询 |      |
| 磅房人员  |      |      | 主责   |    |    |      |
| 库管员   |      |      | 被动扣减 |    |    | 主责   |
| 财务人员  |      |      |      | 审核 | 主责 |      |

由此得出三个判断：

1. **销售员是全系统录入负担最重的角色**（6 个环节中占 3 个），他的操作效率直接决定系统是否可用。
2. **库管员在销售流程中没有主动动作**——过磅完成时系统自动扣减库存。库管员的工作重心在采购入库与月末盘点，不在销售出库。
3. **财务人员出现在末端但掌握两个闸门**（结算审核、回款核销），前面所有单据的数据都在他这里收口。

#### 2.3.2 各角色作业特征

| 角色    | 使用频率     | 单次作业时长     | 核心诉求     | 由此产生的界面要求                             |
| ----- | -------- | ---------- | -------- | ------------------------------------- |
| 系统管理员 | 偶尔       | 不限         | 配置一次长期有效 | 权限与字典配置可批量操作，且随 init.sql 预置           |
| 销售经理  | 每日 1～2 次 | 3～5 分钟     | 快速处理待办   | **登录后首页为待办清单**（待审合同、待审超发、待审额度），而非数据看板 |
| 销售员   | 每日多次     | 3～10 分钟    | 少查、少算    | 合同列表直接显示「剩余可下单量」；下单页自动带出合同价与客户信息      |
| 磅房人员  | 每日数十至上百次 | ≤ 2 分钟 / 车 | 快，不能堵车   | 一屏完成选单→皮重→毛重→打单；大按钮、大字号；每车操作不超过 3 次点击 |
| 库管员   | 每日 1～3 次 | 5～15 分钟    | 账实可核对    | 库存页同时展示账面数、当月出入库、上次盘点时间与差异            |
| 财务人员  | 每日多次     | 5～20 分钟    | 一笔钱冲多张单  | 核销页左列未收结算单、右输入到账金额，自动冲抵并可手工调整顺序       |

> 磅房人员的界面要求不是「做好看」，而是作业环境决定的：操作者站立、可能戴手套、身后有车排队。若按标准管理后台的密集表格设计，实际使用中必然出错。此为可用性需求，不是界面美化需求。

### 2.4 运行环境与技术约束

| 项       | 约定                                            |
| ------- | --------------------------------------------- |
| 运行环境    | JDK 21、Spring Boot 3.5.x、MySQL 8.0+/9.x、Nginx |
| 前端环境    | Chrome / Edge 90+，最小分辨率 1366×768              |
| 架构形态    | 前后端分离，前端静态资源由 Nginx 托管，`/api` 反向代理至后端         |
| 鉴权      | JWT 无状态令牌 + HandlerInterceptor，密码 BCrypt 存储   |
| 金额与重量精度 | 金额保留两位小数，重量保留三位小数（吨）                          |
| 字符集     | 全库 utf8mb4                                    |

## 3 功能需求

### 3.1 功能结构

```
煤炭销售管理系统
├── 用户与权限      登录、角色、菜单、用户
├── 客户与合同      客户档案、信用额度、合同签订与审核
├── 煤炭产品与库存  煤种商品、入库、出库、盘点、预警
├── 销售订单与称重  订单录入与修改、过磅称重、磅单打印与作废
├── 结算与财务      结算单生成与审核、回款登记与核销、对账
├── 统计报表        销量趋势、煤种排行、客户排行、回款率
└── 系统管理        数据字典、操作日志
```

### 3.3 业务规则

#### 3.3.1 合同与订单

| 编号  | 规则                                     |
| --- | -------------------------------------- |
| R01 | 无合同不开单，订单必须挂在「执行中」的合同上                 |
| R02 | 一份合同对应多份订单（1:N），N=1 时即一单一合同            |
| R03 | 合同总量控制发生在下单环节：累计下单量超过合同总量×(1+溢短装比例)时拒绝 |
| R04 | 合同按单煤种设计，不做多煤种明细                       |
| R05 | 订单数量为计划量，实际发运以磅单净重为准                   |
| R06 | 合同须经销售经理审核后才可下单                        |
| R07 | 订单创建即生效，不设审核环节                         |
| R08 | 订单的计划量不得小于该订单的已发运量                     |
| R09 | 订单不能更换所属合同；需换合同只能取消原单后重开               |
| R10 | 合同总量用满时自动置为「已完成」，不再接受新订单               |
| R11 | 合同被终止时：未发运订单自动取消；已发运订单可继续完成结算与回款       |

#### 3.3.2 过磅与计量

| 编号  | 规则                                                       |
| --- | -------------------------------------------------------- |
| R12 | 磅单必须挂订单，不允许游离过磅                                          |
| R13 | 一张磅单含两次称重：皮重（空车）、毛重（重车），净重 = 毛重 − 皮重                     |
| R14 | 磅单状态：待称皮重 → 已称皮重 → 已完成 → 已作废；仅「已完成」参与库存与结算               |
| R15 | 单车净重合理性区间 20～40 吨，超出则拦截，防止录入错误                           |
| R16 | 同一车牌本次皮重与历史均值偏差超过 0.5 吨时提示复核                             |
| R17 | 订单累计发运量超过计划量×(1+溢短装比例)时需销售经理审批                           |
| R18 | 磅单在「已完成」之前可直接修改；已完成只能作废重录                                |
| R19 | 未结算的磅单由磅房直接作废，作废时回滚库存与订单发运量，必须填写作废原因并记录操作人与时间；已结算的磅单不可作废 |

#### 3.3.3 库存

| 编号  | 规则                                    |
| --- | ------------------------------------- |
| R20 | 库存为煤场库存：按吨计量、无货位、存在自然损耗               |
| R21 | 支持盘盈盘亏调整，不设事前审批，但必须记录原因、操作人和时间，可在日志追溯 |
| R22 | 库存低于安全库存时在首页预警                        |

#### 3.3.4 结算与回款

| 编号  | 规则                           |
| --- | ---------------------------- |
| R23 | 结算由销售员生成，财务人员审核，审核后才计入应收账款   |
| R24 | 结算单价默认取合同价，允许修改但必须填写改价理由     |
| R25 | 一张结算单可包含多张磅单，支持一车一结与月结汇总两种口径 |
| R26 | 一笔回款可核销多张结算单                 |
| R27 | 金额计算保留两位小数，重量保留三位小数          |

#### 3.3.5 管理控制

| 编号  | 规则                                 |
| --- | ---------------------------------- |
| R28 | 客户信用额度超出时，订单可创建但标记「超信用待审批」，审批前不可过磅 |
| R29 | 业务参数存入数据字典，可配置不写死                  |
| R30 | 操作日志只记录关键动作：登录、审核、作废、删除、盘点调整       |

#### 3.3.6 角色边界

| 编号  | 规则                                                      |
| --- | ------------------------------------------------------- |
| R31 | 销售出库由磅单完成时自动扣减库存，库管员不参与销售出库的确认与放行；库管员的出库操作仅限非销售类（调拨、自用） |
| R32 | 磅房人员只做计量录入，不判断客户信用、不议价、不参与结算                            |
| R33 | 任一角色不得审核本人创建的单据                                         |

> R31 的取舍：磅单本身已含车牌、司机、过磅时间、司磅员四项可追溯信息，具备凭证效力，再由库管签字属重复确认。代价是账实不符时无法区分「计量错误」与「装车错误」，需通过盘点与磅单复核定位。

### 3.4 审核与审批矩阵

| 单据 / 动作 | 发起人  | 审批人       | 前置条件               |
| ------- | ---- | --------- | ------------------ |
| 信用额度调整  | 销售员  | 销售经理      | ——                 |
| 合同生效    | 销售员  | 销售经理      | 合同为草稿状态            |
| 订单生效    | 销售员  | 无需审批      | 合同执行中且余量足够         |
| 磅单完成    | 磅房人员 | 无需审批      | 净重在 20～40 吨区间      |
| 磅单作废    | 磅房人员 | 无需审批      | 未结算且填写原因           |
| 超发放行    | 系统触发 | 销售经理      | 累计发运超计划量×(1+溢短装比例) |
| 结算单生效   | 销售员  | 财务人员      | 关联磅单均已完成           |
| 回款登记    | 财务人员 | 无需审批      | ——                 |
| 盘盈盘亏    | 库管员  | 无需审批（记日志） | ——                 |

设计意图：**审批只设在「承诺」与「确认」两类节点**——合同是承诺，结算是确认。录入、计量、盘点属执行动作，用日志留痕代替审批，避免卡住现场作业。

## 4 业务流程

### 4.1 核心主流程

```
①签合同 ──审核──▶ ②下订单 ──▶ ③空车过磅(皮重) ──▶ 装车 ──▶ ④重车过磅(毛重)
                                                                    │
                                                         净重 = 毛重 − 皮重
                                                                    │
                                              扣库存 + 累加订单发运量 + 生成库存流水
                                                                    │
                                                    ⑤生成结算单 ──审核──▶ ⑥登记回款 ──▶ 核销
```

关键节点：**库存与发运量在「重车过磅完成」那一刻变动**，不在合同签订时，也不在订单创建时。

### 4.2 单据状态机

| 单据  | 状态流转                       | 关键约束          |
| --- | -------------------------- | ------------- |
| 合同  | 草稿 → 待审核 → 执行中 → 已完成 / 已终止 | 仅「执行中」可下单     |
| 订单  | 待发运 → 部分发运 → 已完成 / 已取消     | 有磅单后不可取消      |
| 磅单  | 待称皮重 → 已称皮重 → 已完成 → 已作废    | 仅「已完成」参与库存与结算 |
| 结算单 | 待审核 → 已审核 / 已驳回            | 驳回后销售员可修改重提   |

### 4.3 异常场景处理

| 编号  | 场景                    | 处理方式                           |
| --- | --------------------- | ------------------------------ |
| E01 | 磅单已录完但净重明显异常（如 300 吨） | 系统拦截（R15）；若已保存，作废重录（R19）       |
| E02 | 客户提货到一半不再提货           | 订单保持「部分发运」，可手工关闭为「已完成」，未发部分不再发 |
| E03 | 实际发运量超出计划量            | 超出溢短装范围转销售经理审批（R17）            |
| E04 | 煤质不合格客户要求退货           | 生成红字结算单冲抵，同时走库存入库（P1，本期仅记录备注）  |
| E05 | 结算单财务驳回               | 结算单退回「待审核」前状态，销售员修改后重新提交       |
| E06 | 客户付款多于单张结算单金额         | 回款可核销多张结算单，余额留存为预收款            |
| E07 | 客户付款少于应收              | 部分核销，结算单保留未收余额，继续计入应收          |
| E08 | 合同提前终止                | 未发运订单自动取消，已发运可继续结算（R11）        |
| E09 | 盘点发现账实不符              | 生成盘盈/盘亏调整记录，写明原因，库存随之修正（R21）   |
| E10 | 磅房网络中断无法录入            | 纸质磅单先行，网络恢复后补录，补录时须标注实际过磅时间    |

## 8 验收标准

1. 完整走通一笔业务：签合同 → 审合同 → 下订单 → 过磅 → 结算 → 审核 → 回款，数据前后一致。
2. 用 6 个角色分别登录，菜单与操作权限符合 2.2 节表格。
3. 库存数量 = 期初 + 入库 − 出库 ± 盘点调整，且可逐笔追溯到磅单与入库单。
4. 数据库重建后执行 init.sql，系统立即可用，无需手工配置权限。
5. 单据金额可反算：结算金额 = Σ(磅单净重 × 单价)，误差为 0。
6. 任一磅单作废后，库存与订单发运量恢复至作废前状态。
7. 合同用满或终止后，后续下单被正确拒绝并给出明确提示。
8. 未携带令牌访问业务接口返回 401；越权访问返回 403。
