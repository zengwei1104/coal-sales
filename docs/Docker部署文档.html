一、为什么用 Docker

维度传统部署Docker 部署
环境安装手动装 JDK/Maven/Node/MySQL/Nginx 共 5 项只装 Docker 1 项
版本冲突容易遇到（Maven、Node 版本对不上）镜像内锁定版本，无冲突
部署命令多步（装环境→导库→build→启动）docker compose up -d 一步
迁移/重装换机器要重来一遍装 Docker 后 pull 镜像即可
数据库初始化手动逐条导入 SQL首次启动自动建库 + 导入 SQL

二、容器化架构

Docker 容器内部网络
web 容器
Nginx :80
└─ /api 反代 ↓
backend 容器
JDK21 + jar :8080
└─ ↓
mysql 容器
MySQL 8.0 :3306
▲ 宿主机只对外暴露 80 端口

三个容器通过 Docker 内部网络互通（用服务名 backend、mysql 当主机名），宿主机只对外暴露 80 端口。

三、需要准备的文件

给项目添加 3 个文件即可，目录结构：

项目根目录/
├── docker-compose.yml           # 编排三个服务
├── coal-sales/Dockerfile        # 后端镜像
└── coal-web/Dockerfile          # 前端镜像
    └── coal-web/nginx.conf      # 前端 Nginx 配置

3.1 coal-sales/Dockerfile（后端）

# 构建阶段：用 Maven + JDK21 打包
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn clean package -DskipTests

# 运行阶段：只保留 JRE + jar，镜像更小
FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /app/target/coal-sales-0.0.1-SNAPSHOT.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]

3.2 coal-web/Dockerfile（前端）

# 构建阶段
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
RUN npm run build

# 运行阶段：Nginx 托管
FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80

配套 coal-web/nginx.conf：

server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://backend:8080;   # 用服务名 backend
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}

3.3 docker-compose.yml（根目录）

services:
  mysql:
    image: mysql:8.0
    container_name: coal-mysql
    environment:
      MYSQL_ROOT_PASSWORD: 改成你的root密码
      MYSQL_DATABASE: coal_sales
      TZ: Asia/Shanghai
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_general_ci
    ports:
      - "3306:3306"          # 可选，本地工具连库用；生产可去掉
    volumes:
      - mysql-data:/var/lib/mysql
      - ./sql:/docker-entrypoint-initdb.d   # 首次启动自动执行所有 .sql
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      retries: 5

  backend:
    build: ./coal-sales
    container_name: coal-backend
    depends_on:
      mysql:
        condition: service_healthy
    environment:
      DB_USERNAME: root
      DB_PASSWORD: 改成你的root密码
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/coal_sales?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    ports:
      - "8080:8080"          # 可选，调试用
    restart: unless-stopped

  web:
    build: ./coal-web
    container_name: coal-web
    depends_on:
      - backend
    ports:
      - "80:80"
    restart: unless-stopped

volumes:
  mysql-data:

四、虚拟机安装 Docker

虚拟机（RHEL/CentOS 系）里只需装 Docker 一个东西：

# 安装 Docker 及 Compose 插件
sudo dnf install -y docker docker-compose-plugin

# 启动并设开机自启
sudo systemctl enable --now docker

# 验证
docker --version
docker compose version
如果 docker-compose-plugin 找不到，可改用 sudo dnf install -y docker-compose（旧版命令为 docker-compose，新版为 docker compose）。

五、一键部署流程

# 1. 把项目代码弄进虚拟机
git clone https://github.com/你的用户名/coal-sales.git
cd coal-sales

# 2. 一条命令起全套（首次自动 build 镜像 + 建库 + 导数据）
docker compose up -d --build

# 3. 查看状态
docker compose ps
docker compose logs -f backend    # 看后端日志

六、验证与访问

1. 查虚拟机 IP

# 或
hostname -I

输出中形如 192.168.x.x 的即虚拟机 IP。

2. 浏览器访问

http://虚拟机IP            # 系统前端页面
http://虚拟机IP/api/...    # 接口（经 Nginx 转发）

3. 网络模式要求

网络模式能否从 Windows 访问说明
桥接 Bridged✅ 能虚拟机与宿主机同网段，推荐
NAT⚠️ 需配端口转发要手动转发 80 端口
仅主机 Host-only✅ 能仅宿主机与虚拟机互通
若为云服务器，则用公网 IP，并在安全组放行 80 端口。

七、注意事项

#事项说明
1SQL 脚本容器首次启动会自动执行 sql/ 下所有脚本（01~07 按文件名顺序），但 init.sql 里的 SOURCE 命令在容器内不适用，建议只挂载 01~07，跳过 init.sql
2数据库账号容器默认建 root（用 MYSQL_ROOT_PASSWORD），后端 DB_USERNAME=root；如需独立账号，加一个初始化脚本专门建用户
3密码compose 里的 MYSQL_ROOT_PASSWORD 和 DB_PASSWORD 要一致，且不要提交进 git
4端口暴露3306/8080 暴露给宿主机仅供调试；生产建议只暴露 80
5数据持久化mysql 数据存在 mysql-data 卷里，容器重启不丢数据
6更新代码改代码后 docker compose up -d --build 重新构建对应镜像即可
